Restaurant Billing Flow Notes

This document explains where a KOT + Bill action fits across common restaurant and counter-kitchen workflows.

Counter Kitchen

Theater, mall, food court, quick-service counter

The cashier takes the order, sends it to kitchen, gives a running bill or token copy, then the salesman completes payment later.

Send to order Mark served Print running bill Open checkout Manual confirm
Waiter Table Service

Classic dine-in restaurant

The waiter can print a table bill before payment, but serving state should normally reflect the actual kitchen/table lifecycle.

Send KOT Kitchen prepares Optional table bill Payment Confirm final bill
Token Pickup

Customer pays or receives token and waits

Marking served can be acceptable when it means the kitchen queue has accepted or released the order, not that dining is complete.

Create order Print KOT/token Serve status update Checkout remains manual
Manual Finalization

Why final confirm stays manual

Customer, discount, credit, payment split, delivery charge, and final receipt copy are billing decisions. The system should not finalize those automatically from the KOT button.

Current recommendation

KOT + Bill button behavior

For now, enable the button only in billing counter mode. The button should send the order, mark it served, print ongoing order details, and open checkout. It should not confirm the sale automatically.
