Restaurant Billing Flow Notes

This document explains where a KOT + Bill action fits across common restaurant and counter-kitchen workflows. In this app, the feature is scoped to billing-counter-enabled restaurant mode.

Counter Kitchen

Theater, mall, food court, quick-service counter

The cashier takes the order, sends it to kitchen, gives an Order Summary or token copy, then the salesman completes payment later.

Send to order Mark served Print Order Summary Open checkout Manual confirm
Waiter Table Service

Classic dine-in restaurant

The waiter can print a table bill before payment, but serving state should normally reflect the actual kitchen/table lifecycle. If this shop still runs table orders from the billing counter, the dine-in allowance setting decides whether KOT + Bill is available.

Send KOT Kitchen prepares Optional table bill Optional auto serve Payment Confirm final bill
Token Pickup

Customer pays or receives token and waits

Marking served can be acceptable when it means the kitchen queue has accepted or released the order, not that dining is complete.

Create order Print KOT/token Serve status update Checkout remains manual
Manual Finalization

Why final confirm stays manual

Customer, discount, credit, payment split, delivery charge, and final receipt copy are billing decisions. The system should not finalize those automatically from the KOT button.

Current recommendation

KOT + Bill button behavior

KOT + Bill is enabled only for billing-counter restaurant mode and only when the app setting allows it. It sends the order, optionally marks items served, prints an Order Summary, and opens checkout. It never confirms the sale automatically.

App Settings

Control flags

  • ENABLE_KOT_BILL_BUTTON controls whether KOT + Bill and the ongoing-order Pre-Bill button are visible.
  • ENABLE_SEND_TO_KITCHEN_BUTTON controls whether the normal Send Kitchen button is visible. Default should be true when this key is missing, so old API users keep existing behavior.
  • KOT_BILL_AUTO_MARK_SERVED controls whether the KOT + Bill flow automatically marks all current order items as served.
  • KOT_BILL_ALLOWED_FOR_DINE_IN controls whether KOT + Bill can be used when a table is selected or the delivery method is Dine In.

Auto Serve On

KOT_BILL_AUTO_MARK_SERVED=true

Example: mall food counter. The cashier sends the order, the kitchen queue is considered released, the Order Summary prints, and checkout opens for payment.

KOT + Bill Send order Mark served Print Order Summary Manual confirm
Auto Serve Off

KOT_BILL_AUTO_MARK_SERVED=false

Example: dine-in counter/table service. Staff can print the running bill early, but item status stays as new, started, or preparing until someone marks served manually.

KOT + Bill Send order Keep kitchen status Print Order Summary Manual confirm
Ongoing Orders

Pre-Bill button

Ongoing orders can show a Pre-Bill button when ENABLE_KOT_BILL_BUTTON is enabled and the page is running in billing counter mode. This prints the current ongoing order details with the document title Order Summary. It does not mark served and does not confirm the order.
